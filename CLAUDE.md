# Bingr-beheer: werkafspraken

- Openbare repo met het beheer-dashboard van Bingr (https://beheer.bingr.online) en de Supabase Edge Function `admin`. Het beheer hoort niet in de andere repo's (iptv-ios-appletv, bingr-website, bingr-android), behalve het schema (zie onder).
- Openbaar betekent: geen geheimen, geen persoonsgegevens (e-mailadressen, namen, account-id's, tickets, exports, ook niet als testdata of in screenshots) en geen logs met servergegevens (secrets, interne adressen, FTP-mappen, serverantwoorden met gebruikersgegevens) in bestanden, commits of workflow-logs.
- Wijzigingen hier komen **nooit** in de changelog (`docs/changelog.json` in iptv-ios-appletv), niet op bingr.online en niet in release-notities. Ze krijgen ook geen buildnummer.
- Geheimen alleen als GitHub-secrets (zie README.md), nooit in de repo of in een log. De publieke Supabase-URL en de publishable key (`web/config.js`) mogen er wel in.
- GitHub Actions vast op een commit-SHA (tag als commentaar), de Supabase CLI op een vaste versie; unittests van `admin` blokkeren de deploy.
- Deploy:
  - `web/` → workflow *Dashboard* (`deploy-site.yml`): FTPS-upload naar `FTP_DIR` (de map van het subdomein), of zonder `FTP_DIR` naar de hoofdmap van de FTP-login (eigen FTP-account van het subdomein; nooit als dat de webmap van bingr.online is), daarna controle van https://beheer.bingr.online/. Houd `noindex` in `web/index.html` en `Disallow: /` in `web/robots.txt`. Houd de Content-Security-Policy (`web/.htaccess` en de meta in `web/index.html`) strikt: geen inline scripts, styles of `style=`-attributen (breedtes e.d. via `element.style`).
  - `supabase/functions/admin` → workflow *Admin-functie* (`deploy-admin.yml`): deploy van `admin`, de secrets BINGR_ADMIN_USER / BINGR_ADMIN_PASSWORD (en optioneel BINGR_SMTP_*), en een rooktest (fout wachtwoord = 401 met CORS voor https://beheer.bingr.online).
  - Controleer na elke push met `gh run list -R LRvdLinden/bingr-beheer` dat de workflows geslaagd zijn.
- Aanleveren van buildpakketten (H3): iptv-ios-appletv en bingr-android pushen versleuteld naar de **privé** repo LRvdLinden/bingr-inbox (secret `BINGR_INBOX_TOKEN` daar, alleen Contents: write op bingr-inbox); geen enkele andere repo krijgt een schrijftoken op bingr-beheer (`BINGR_BEHEER_TOKEN` is vervallen). *Builds* haalt de inbox elke 15 minuten op met `BINGR_INBOX_READ_TOKEN` en verwerkt ook de inbox-branches in deze repo (alleen de Beheer-app, met GITHUB_TOKEN). Tokens nooit in een clone-/push-URL (kopregel via `GIT_CONFIG_*`).
- `ios/` is de native app Bingr Beheer (SwiftUI, iOS/iPadOS 17+, XcodeGen; eigen versie/build in `ios/project.yml`): workflow *Beheer-app* (`build-ios.yml`) bouwt hem en levert het Xcode-project versleuteld aan voor de map `builds/` op de server (workflow *Builds*); nieuwe functies van het web-dashboard ook in de app overnemen. Nooit in de changelog.
- Buildpakketten (APK, .wgt, Xcode-zips van Bingr en Bingr Beheer) nooit meer in de repo, als release of als onversleuteld artefact op GitHub. Ze staan alleen in de afgesloten map `builds/` op de server van beheer.bingr.online (workflow *Builds*) en zijn alleen op te halen via `dl.php` met een kortgeldige link uit de functie `admin` (uitzondering: de nieuwste Android-APK is openbaar via `dl.php?app=android`, voor de testversie op bingr.online) (acties `builds` / `build_link`, tab Downloads; sleutel = function-secret `BINGR_BUILDS_KEY`, nooit loggen, net als tokens en downloadlinks).
- Function-secrets gelden voor het hele Supabase-project; verander BINGR_SMTP_* hier alleen samen met iptv-ios-appletv (de functie `status` gebruikt ze ook).
- Het databaseschema (ook `announcements`, `admin_login_attempts`, `admin_audit` en de functies `bingr_admin_*`), `status`, `device-auth` en `web-proxy` staan in iptv-ios-appletv (`supabase/`, workflow *Backend*). Heeft het dashboard een schemawijziging nodig, dan gaat die daar in `supabase/schema.sql`, zonder changelog-item.
- `supabase/functions/_shared/mail.ts` is een kopie van die in iptv-ios-appletv; houd ze gelijk.
- CORS van `admin`: https://beheer.bingr.online en localhost voor alles; https://bingr.online alleen voor `unsubscribe` (afmeldpagina bingr.online/unsubscribe/).
- Commitberichten in het Nederlands.
